# ヒトマネ入稿ツール（hitomane_agent）設計書

2026-11-16

## 目的と理由

求人媒体「ヒトマネ（HITO-Manager）」への入稿と取り下げを、Q-mate 入稿ツール（`qmate_agent`）と同じように、
操作画面のボタンから自動で行えるようにする。

今の手作業：

- 原稿は、ヒトマネ用の GAS（③予約リストを一括実行）が「ヒトマネ出力_…」シートとして作る。⑤で検品する。
- 入稿は、出力シートを CSV にして、ヒトマネ管理画面で「ファイル取込予約」する。
- 取り下げは、ヒトマネ全体の上限（5万件）があるため、入れる前に担当者が件数を確かめて手で行う。
  募集管理で掲載開始日・掲載終了日の範囲で検索 →「ファイル取出予約」→ 取り出した CSV の開始日・終了日を2年くらい前、
  ステータスを「非掲載」に書き換え →「ファイル取込予約」。
  終了日が未来のままだと、非掲載にしても残り続けるため（ヒトマネは入れた日から1年後を終了日にする）。

最終的には Q-mate 版と1つのツールに統合したい。今回はまず、Q-mate 版を変えずに、ヒトマネ用の別ツールとして作る（ユーザーの選択）。

## 目標

1. 出力シートの入稿：AI 用スプレッドシートの「ヒトマネ出力_…」シートを操作画面に並べ、チェックしてから
   ヒトマネに取り込む。取り込みの完了・エラーを予約一覧で確かめて、画面に出す。
2. 入稿前のチェック：⑤検品と同じ項目に、Q-mate 版で入れた検出（#REF! などのエラー値、応募先と会社の照合）を足す。NG なら入稿しない。
3. 取り下げ：条件を指定して「取り出しと件数の確認だけ」→「取り下げる」。開始日・終了日を2年前、ステータスを非掲載に書き換えて取り込む。
   確認のあと同じ日・同じ条件なら、取り出しを省く（Q-mate 版と同じ）。
4. ログイン：通勤用スプレッドシートの「Q-mateログイン情報」シートと同じ考え方で、ヒトマネのログイン情報を持つ。
5. 更新：操作画面の「更新」ボタンで GitHub から最新にできる（Q-mate 版と同じ仕組み）。

## 目標にしないこと（今回）

- 原稿を作る部分（③の GAS）をツールに移すこと。次の段階で行う（③の Code.gs をもらってから）。
- 入稿予定表からの日付指定の自動実行。今回は、担当者が出力シートを選んで入稿する。
- 自動での取り下げ。取り下げは必ず担当者が条件と件数を確かめてから実行する（Q-mate 版と同じ方針）。
- Q-mate 版（`qmate_agent`）の変更。

## 失敗とみなすこと（動いても困ること）

- #REF! などのエラー値や、ほかの会社の応募先が入ったまま入稿されること。
- 取り下げで、指定した条件の外の原稿（ほかの会社、ほかの期間）まで非掲載にすること。
- 予約一覧でエラーになっているのに「成功」と表示すること。
- 原本の運用ファイルを書き換えること（ツールが読むのは AI 用のスプレッドシートだけ）。

## 前提・制約

- ヒトマネ管理画面（`https://kanri.hitomgr.jp/m66w/`）は、決まったネットワークからしか開けない。
  クラウドの作業環境からは 403 になるため、ツールはユーザーのパソコンで動かす。画面の作りも、ここからは直接見られない。
- 1つのログインで全社の原稿を扱う（一覧の会社名は「CB株式会社(B001)」の形）。
- 取り込み：トップの「ファイルを取込む」、または募集管理の「ファイル取込予約」。ダイアログ「募集情報のファイルを取り込む（新フォーマット）」で
  ファイルを選び「ファイル取込予約」。「既存原稿と同じ募集番号の原稿を上書きせずに取り込む」は外したまま（同じ募集番号は上書き）。
- 取り出し：募集管理の検索欄（フリーワード＋項目、掲載開始日〜、掲載終了日〜、雇用形態、ステータス：掲載のみ／非掲載のみ、旧フォーマット原稿のみ）
  →「ファイル取出予約」。
- 予約一覧：リクエスト日時・データ種別（募集管理（新）など）・ステータス（待機中 → 完了）・詳細（取出しファイルのリンク、件数、処理時間）・削除予定日。
  「最新を表示する」で更新。取り込みの結果・エラーもここに出る。ほかの人の予約があると待機中のままになることがある。
- 出力シートは新FMT（192列）と旧FMT（109列）がある。取り込みダイアログは「新フォーマット」。
- ヒトマネの全原稿数は上限5万件（今ちょうど5万件）。

## 作り方の候補

| 案 | 内容 | よいところ | 気をつける点 |
|---|---|---|---|
| 1 | Q-mate 版に「媒体」を足して1つのツールにする | 統合の目的に最初から沿う。直しが両方に効く | 最初に Q-mate 専用のところを分ける作業が要る |
| **2（選択）** | ヒトマネ用の別ツールを作る | Q-mate 版の運用に影響がない | 統合のときに合わせ直す手間がある |

ユーザーは案2を選んだ。統合しやすくするため、同じリポジトリの `hitomane_agent/` フォルダに、`qmate_agent` を写した形で作る
（部品の名前と分け方をそろえる）。

## 決まっていること（作り方）

- フォルダ：`hitomane_agent/`。操作画面（app.bat）、設定（config/settings.json・settings.local.json）、state、output を別に持つ。
  更新ボタンは `hitomane_agent` フォルダを取り込む。
- 読むスプレッドシート：【AI用】ヒトマネ 求人原稿自動生成（`1sDLw8aMXmkQi9Uy4fhQMf3g4GqKhh7fd8TJEIWe1DzA`）。原本は読まない・書かない。
- 出力シート：名前が「ヒトマネ出力_」で始まるシート。列の形（新FMT／旧FMT）は見出しで判断する。
- 入稿の前に必ずチェックし、NG なら入稿しない。チェックのあとシートが変わっていたら入稿しない（Q-mate 版と同じ）。
- 取り下げで書き換える列：開始日・終了日（実行した日の2年前の日付）、ステータス（非掲載）。ほかの列は取り出したまま。
- 取り下げの条件：会社（フリーワード）、掲載開始日の期間、ステータスは「掲載のみ」。
  取り出したあとも、ツール側で会社と期間に合う行だけに絞ってから書き換える（検索の取りこぼし・取りすぎを防ぐ）。
- 同じ募集番号は上書きされるので、取り下げの CSV は取り出した募集番号のまま取り込む。
- ログイン情報は、通勤用スプレッドシートの「Q-mateログイン情報」シートに「ヒトマネ」の行を足して読む
  （共有が制限付きでないときはパスワードを使わない、という Q-mate 版の決まりもそのまま）。
- 画面の操作は Playwright。結果待ちは「最新を表示する」を押して、ステータスが完了・エラーになるまで待つ。待っているあいだは経過を出す。

## 設計の段階で私（Claude）が決めたこと（確認してください）

- 取り下げで入れる日付：開始日・終了日とも「実行した日の2年前の日」（例：2026/11/16 に実行 → 2024/11/16）。
- 取り下げの会社の選び方：ヒトマネの土台の「会社情報マスター」の会社名と拠点コードから選ぶ。取り出したあとは、
  拠点コード（一覧の「CB株式会社(B001)」の B001 の部分）が合う行だけを書き換える。フリーワードの検索で
  ほかの会社が混ざっても、ここで除く。
- 入稿の前に、募集管理の全件数（今は「全50000件」）を読み、入れる件数を足すと5万件を超えるときは、確認の画面でそのことを知らせる
  （止めはしない。先に取り下げるかどうかは担当者が決める）。
- 1つの出力シートが1万行を超えるときは、Q-mate 版と同じく1万行ずつに分けて取り込む（ヒトマネの上限が分かれば合わせる）。

## 作る人に任せること

- ヒトマネ管理画面のボタン・入力欄・予約一覧の行の見分け方（セレクター）。クラウドからは画面を見られないので、
  まずユーザーのパソコンで動く「画面調査」コマンドを作り、ログイン後のトップ・募集管理・取込ダイアログ・予約一覧の
  HTML とスクリーンショットを output に保存してもらい、それを見て決める。
- 取り込む CSV の文字コード・改行・見出しの形。画面調査のときに「ファイル取出予約」で1件だけ取り出した CSV を見て、同じ形にそろえる。
- 予約一覧で、自分が出した予約の行の見分け方（リクエスト日時・データ種別・ファイル名）。
- ⑤検品のチェック項目の細かい中身（マニュアルにある件数・空欄・勤務地重複は必ず入れる）。
- 予約一覧のエラー表示の文言の読み取り方。

## 段階

1. 画面調査コマンド（`python -m hitomane_agent survey`）と、ログイン・設定の確認。ユーザーに実行してもらい、結果を受け取る。
2. 入稿（出力シートの一覧・チェック・取り込み・予約一覧での確認）。
3. 取り下げ（確認だけ・取り下げ・取り出しの省略）。
4. （次の設計）原稿を作る部分を GAS からツールに移す。統合。
