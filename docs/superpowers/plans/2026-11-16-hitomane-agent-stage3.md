# ヒトマネ入稿ツール 第3段階（取り下げ）Implementation Plan

2026-11-16

**Goal:** 掲載開始日の期間を指定して、その期間の掲載中の原稿を取り出し、開始日・終了日を2年前、ステータスを「非掲載」に書き換えて
取り込み直す。「確認だけ」（取り出して件数を見る）と「取り下げる」に分け、同じ日・同じ条件なら確認のときのファイルを使う。

## 分かったこと（画面調査・2026-11-16）

- **会社 ＝ ログインするアカウント。** m66w の拠点は「CB株式会社（B001）」の1つだけで、50,000件すべてがこの拠点。
  GritMate（Mat001）で検索すると0件。ほかの会社は別のアカウント。会社情報マスターの拠点コードは会社をまたいで同じ（B001 が6社）なので、
  拠点コードだけでは会社を区別できない。→ 引き継ぎ資料の「1つのアカウントで全社」は誤り。5万件の上限もアカウントごと。
- 掲載開始日の検索は、隠れた欄 `posted_start_from[year]`・`[month]`・`[day]`（`_to` も）が送られる。画面の入力欄（`#posted_start_from`）と
  隠れた欄の両方に入れる。「掲載のみ」は `#search_condition_posted_only`。
  例：掲載のみ・開始日 2026/11/17 → 5,000件、2026/11/01〜11/16 → 10,000件、2024/01/01〜2026/10/31 → 34,990件。
- 取出・取込ファイル一覧の状態は 待機中 → 進行中 → 完了。

## 決めたこと（Claude が決めた。違えば直す）

1. 条件は「掲載開始日の期間（から・まで）」と「掲載のみ」。会社は、ログインしているアカウント（settings の login_user）。
2. 取り出したあと、ツール側でも絞る：拠点コードと拠点名がアカウントの拠点（拠点の一覧 `m_branches` の行）と同じ、開始日が期間内、
   ステータスが「掲載」の行だけ書き換える。外れた行は取り込まない（件数を出す）。アカウントに拠点が2つ以上あるときは止める。
3. 書き換えるのは 開始日・終了日（実行した日の2年前の日。2/29 は 2/28）とステータス（非掲載）だけ。ほかの列は取り出したまま。
4. 「確認だけ」：取り出して書き換えたファイルを `output/取り下げ_<日付>_<から>-<まで>/` に作り、`state/takedown_prepared.json` に残す。
   ヒトマネには取り込まない。
5. 「取り下げる」：同じ日・同じアカウント・同じ条件の「確認だけ」があれば、そのファイルを使う（取り出しを省く）。なければ取り出しから。
   件数と期間を見せて確認してから、1万行ずつ取り込む。結果は `state/takedown.json`。
6. 自動ではやらない。コマンドは `--yes` がなければ確認を聞く。操作画面は「確認だけ」のあとでないと「取り下げる」を押せない。

## Tasks

1. `takedown.py`：条件、2年前の日、取り出した CSV の絞り込みと書き換え、確認ファイルの保存と探し方。テスト：`tests/test_takedown.py`。
2. `site.py`・`exporter.py`：募集管理で期間・掲載のみで検索 → 件数 → 「ファイル取出予約」→ 取出ファイル一覧で完了を待って CSV を落とす。
   拠点の一覧からアカウントの拠点を読む。にせの画面に、日付の検索・拠点の一覧・条件どおりの CSV の取り出しを足す。
3. コマンド `takedown --from YYYY/MM/DD --to YYYY/MM/DD [--prepare-only] [--yes]`。テスト：確認だけで取り込まない、確認のファイルを使う、
   確認を聞く、0件なら止める。
4. 操作画面に「取り下げ」の欄（期間、確認だけ、取り下げる）。
5. 実物：「確認だけ」は利用者に聞かずに動かしてよい（取り出すだけ）。「取り下げる」は利用者に条件と件数を見せて確認してから。
