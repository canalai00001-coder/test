# ヒトマネ入稿ツール 第2段階（入稿）Implementation Plan

2026-11-16

**Goal:** 【AI用】スプレッドシートの「ヒトマネ出力_…」シート（または CSV）をチェックし、問題がなければヒトマネに「ファイル取込予約」して、
取込ファイル一覧で結果を確かめる。コマンド（list / check / upload）と操作画面（app.bat）から使える。

**元にするもの:** 設計書 `docs/superpowers/specs/2026-11-16-hitomane-agent-design.md`、画面調査の結果
`docs/superpowers/specs/2026-11-16-hitomane-screen-survey.md`、Q-mate 版の `checks.py`・`csv_export.py`・`uploader.py`・`__main__.py`（check/upload）・`app.py`。

## Global Constraints

- `qmate_agent/` は変えない。
- テストを先に書く。画面の操作は `tests/fake_hitomane.py` を実物と同じ作り（画面調査で分かったセレクター）にしてテストする。
- 取り込みは、チェック済み・チェック後に変わっていない・NG でない・同じ内容を入稿済みでない、のすべてを満たすときだけ。
  コマンドは `--yes` がなければ確認を聞く。
- パスワードはログ・ファイルに出さない。

## 決めたこと（Claude が決めた。違えば直す）

1. **新フォーマット（192列）だけ取り込む。** 見出しが新FMT(テンプレ)と1列でも違えば NG。旧FMT（109列）のシートは「旧フォーマットは取り込めません」で NG。
2. **AI による中身のチェック（Q-mate 版の ai_review）は今回入れない。** ルールのチェックだけ。あとで足す。
3. **応募先メールの照合は入れない。** ヒトマネの CSV には応募先メールの列がないため。代わりに、1枚のシートに拠点コードが2つ以上あれば注意を出す。
4. 「お仕事番号」（メモの形）と、給与の下限・上限・画像名・勤務地が合わないものは NG（Q-mate 版と同じ）。会社名は、メモでは略称のことがある
   （例：`canal benefits株` と拠点 `CB株式会社`）ので見ない。
5. 取込ファイル一覧の結果の読み方：取り込み後に新しくできた行の「ステータス」が「完了」で、詳細にエラーらしい文言（エラー・失敗・不正・できません）が
   なければ成功。待機中・処理中のあいだは「最新を表示する」を押して待つ。完了以外で止まったときや、時間内に終わらないときは失敗として画面の写真を残す。
   **実物の完了・エラーの表示はまだ見ていない** ので、Task 6 で1件取り込んで確かめてから直す。
6. 入稿前に募集管理の「全N件」を読み、N＋入れる件数が 50000 を超えるときは、確認のときに知らせる（止めない）。
7. 1万行を超えるシートは、1万行ずつの CSV に分けて順に取り込む。

## チェックの中身（`config/rules.json`）

| 種類 | 内容 |
|---|---|
| エラー | 見出しが新FMTの192列と違う／旧FMT |
| エラー | 原稿が0件 |
| エラー | どこかのセルに `#REF!` などのスプレッドシートのエラー値 |
| エラー | Shift_JIS（cp932）で書けない文字（絵文字など）。CSV にできないため |
| エラー | 必須の列（募集番号・開始日・終了日・ステータス・拠点コード・募集職種・雇用形態・基本給_給与タイプ・勤務地_都道府県 など）が空欄 |
| エラー | 「あり・なし」の列（85列）が「あり」「なし」以外（空欄も。ヒトマネはエラーにする） |
| エラー | 開始日・終了日が `YYYY/MM/DD` でない、開始日が終了日より後 |
| エラー | ステータスが「掲載」「非掲載」以外 |
| エラー | 基本給_最低額・最高額が数字でない、最低額が最高額より大きい |
| エラー | お仕事番号（メモ）と基本給・画像名1・勤務地が合わない |
| エラー | 同じ募集番号がシート内に2つ以上（後の行で上書きされてしまう） |
| 注意 | 勤務地（都道府県＋市区町村）がシート内で重複（⑤検品の勤務地重複） |
| 注意 | 1枚のシートに拠点コードが2つ以上 |
| 注意 | いつも入っている列（PR・給与・勤務時間_補足・応募資格 など）が空欄 |

## Tasks

### Task 1: 見出しとチェック（`headers.py`・`checks.py`・`config/rules.json`）
- `tests/test_checks.py`：見本の1行（取り出し見本と同じ形）を OK にし、上の表の項目を1つずつ壊して error / warning になることを確かめる。
- 見出しは `headers.py` に新FMTの192列を持つ（取り出した CSV と新FMT(テンプレ)が完全に同じだった）。

### Task 2: CSV にする（`csv_export.py`）
- cp932・BOM なし・CRLF・必要なときだけ `"` で囲む。セルの中の改行（シートでは LF）は CRLF にする。1万行ずつに分ける。
- `tests/test_csv_export.py`：取り出し見本を読み込んで書き出すと、元のバイト列と同じになる。分割の件数。書けない文字は例外。

### Task 3: シートを読む（`sheet.py`）
- 「ヒトマネ出力_」で始まるシートの一覧と中身。`--csv` のときは CSV（cp932 か UTF-8）を読む。

### Task 4: 取り込み（`site.py`・`uploader.py`）
- `site.py`：ログイン・一覧の行・「最新を表示する」など、画面調査と共通の部品。
- `uploader.py`：募集管理の件数を読む → 取込ファイル一覧のいちばん上の行を覚える → 取込ダイアログ（iframe）で `#file_csv` にファイル、
  `#duplicate_check_term` は外したまま、`a.btn_operation_btn02` を押す（確認ダイアログは OK）→ 取込ファイル一覧で新しい行の結果を待つ。
- にせの画面に取込ダイアログの送信と取込ファイル一覧の行（待機中 → 完了／エラー）を足す。テスト：成功、エラー、時間切れ、チェック欄が付いていたら外す。

### Task 5: コマンド（`__main__.py`）
- `list`：出力シートの一覧とチェックの状態。
- `check (--sheet 名前 | --csv パス)`：チェックして `output/<名前>/report.html`・CSV・`state/reviews.json`。
- `upload (--sheet 名前 | --csv パス) [--yes] [--dry-run]`：止める条件を見て、件数・全件数を出して確認 → 取り込み → `state/uploaded.json`。
- テスト：check していない／変わった／NG／入稿済みで止まる。dry-run で取り込まない。

### Task 6: 実物で1件確かめる（利用者に確認してから）
- 画面調査で取り出した `取り出し見本.csv`（canalbenefits100174 の1件）を、**中身を変えずに** `upload --csv` で取り込む。
  同じ募集番号は上書きされるので、原稿の中身は変わらない。
- 取込ファイル一覧の完了の表示を見て、決めたこと 5 を直す。

### Task 7: 操作画面（`app.py`・`app.bat`）
- Q-mate 版と同じ形のブラウザ画面：出力シートの一覧 → 「チェック」→ 結果を見る → 「入稿」（件数・全件数・注意を出して確認）。
