# Q-mate 入稿チェック・入稿ツール

「【AI用】Q-mate 求人原稿自動生成」スプレッドシートの GAS が作った出力シートを読み込み、
内容をチェックしてから CSV にして Q-mate に入稿します。

原稿を作るのは今まで通り GAS です。このツールが受け持つのは、そのあとの
「確認 → CSV 書き出し → 入稿」です。

## 流れ

```
実行設定シートに予約 → GAS で原稿生成（出力_G1_… シート）→ GAS で検品（検品シート）
   │
   ▼
① check   出力シートを読んでチェック
          ・ルールチェック（下の表）
          ・Claude による中身のチェック（職種名と仕事内容のズレ、キーワードと原稿の食い違い、
            テンプレートの差し込み漏れ、誤字など）
          → output/<シート名>/report.html と CSV を作り、
            スプレッドシートの「AIチェック結果」シートにも書き出す
   │
   ▼
② 人が確認  レポートを見て、問題があればシートを直して ① をやり直す
   │
   ▼
③ upload  CSV を Q-mate に入稿し、結果画面の文言とスクリーンショットを保存
```

upload は、次のどれかに当てはまると入稿せずに止まります。

- check をしていない
- check のあとにシートの内容が変わった
- AI チェックをしていない（`--no-ai` で check した）※ `settings.json` の `require_ai_check` が true のときだけ
- 判定が NG
- 検品シートの判定が ✅OK 以外
- 同じ内容をすでに入稿済み

## ルールチェックの中身

GAS の検品シートと同じ項目に加えて、マニュアルと記録用シートに書かれている運用ルールを見ます。
設定は `config/rules.json` にまとめてあるので、運用が変わったらそこを書き換えます。

| 種類 | 内容 |
|---|---|
| エラー | 「\|必須」の列が空欄 |
| エラー | 給与形態が月給・日給などのときに基本給・労働時間が空欄 |
| エラー | 年齢制限・性別制限が「あり」なのに事由が空欄 |
| エラー | 給与の下限・上限が数値でない、下限が上限より大きい |
| エラー | メモと給与下限・上限・画像番号・勤務地が一致しない |
| エラー | 月給の下限が「2026.10.1～給与下限」を下回る（職種はメモの職種番号、夜勤の有無は勤務時間の書き方で判断） |
| エラー | 勤務時間は夜勤なしなのに求人ボックス用職種名が「夜勤あり」（またはその逆） |
| エラー | 求人ボックス用職種名が50文字を超える |
| 注意 | 応募資格・勤務時間・休日・キャッチコピー・待遇・仕事内容（重め・軽め以外）に絵文字が残っている（10/22 の変更） |
| 注意 | 休日に「年間休日125日」が残っている（10/13 の変更） |
| 注意 | キーワードに削除済みの語（土日祝休み・完全週休二日制・平日のみOK・三交代制）が入っている |
| 注意 | 夜勤なしの原稿に夜勤系のキーワードが入っている |
| 注意 | 同じシート内で求人ボックス用職種名や勤務地が重複している |

「年齢制限の有無」が空欄の原稿は、チェックの前に「なし」を入れて扱います（CSV にも「なし」が入ります。シートは書き換えません）。
テンプレート(固定列) のこの列が空欄で、GAS の検品でも見ていないためです。
ほかの列にも同じことをしたい場合は、`rules.json` の `blank_defaults` に追加します。

会社ごとの応募先メールを確かめたい場合は、`rules.json` の `company_emails` に
`"GritMate株式会社": "xxx@example.com"` のように入れると、メモの会社名と照らし合わせます。

## セットアップ

```bash
cd qmate_agent
pip install -r requirements.txt
playwright install chromium
```

### 1. スプレッドシートを読めるようにする

1. Google Cloud でサービスアカウントを作り、JSON キーを `service_account.json` という名前でこのフォルダに置く
   （git には入らないようにしてあります）
2. スプレッドシートを、サービスアカウントのメールアドレスに「編集者」で共有する

### 2. Claude の API キー

```bash
export ANTHROPIC_API_KEY=...
```

### 3. Q-mate のログイン情報

ID とパスワードはファイルに書かず、環境変数で渡します。

```bash
export QMATE_ID=...
export QMATE_PASSWORD=...
```

### 4. Q-mate の CSV 入稿画面の設定

`config/settings.json` の `qmate` は、2026/10/27 に実際の画面（求人情報一覧 →［CSV取込］）を見て埋めてあります。

| 項目 | 値 | 画面のどこか |
|---|---|---|
| `upload_url` | `https://m.q-mate.jp/job_offers/bulk_new?co=27859` | CSV取込（AspiRove株式会社）のページ |
| `file_input_selector` | `#file` | ［ファイルを選択］ |
| `upload_button_selector` | `#csv_import_submit` | ［アップロード］ |
| `result_selector` | `#csv_import_log` | 「最後に受付したCSV取込」の表 |
| `success_pattern` | `成功` | 表のステータス欄 |

Q-mate の取り込みは、アップロードを受け付けたあとに裏で処理されます。
そのため upload は「最後に受付したCSV取込」の表が取り込み前と変わり、
「成功」かエラーの表示（「エラー内容を見る」など）になるまで、
`result_poll_interval_ms`（5秒）ごとに `result_poll_times`（36回＝約3分）ページを読み込み直します。
それでも終わらないときは失敗扱いで止まるので、CSV取込画面で結果を見てください。
原稿の本数が多くて毎回時間切れになるなら `result_poll_times` を増やします。

`co=27859` は AspiRove株式会社 の番号です。Q-mate の CSV は会社ごとに分けて入稿する決まりなので、
別の会社の原稿を入稿するときはその会社の CSV取込ページの URL に変えてください。
アップロード画面の「原稿確認依頼メール」は送らない設定（Q-mate の初期値のまま）です。

### 5. 入稿予定表からの自動実行（schedule）の準備

`schedule` は、スプレッドシートの「入稿予定表」に書いた行をもとに、
実行設定への予約 → GAS での生成 → チェック → 入稿 までを続けて行います。

入稿予定表の「通勤/入寮」（E列）の値で、生成に使うスプレッドシートを切り替えます。

| 通勤/入寮 | 生成するスプレッドシート | 合言葉の環境変数 |
|---|---|---|
| 通勤（空欄も通勤） | 【AI用】Q-mate 求人原稿自動生成（通勤用 GAS） | `QMATE_GAS_TOKEN` |
| 入寮 | AI用【入寮】Q-mate 求人原稿自動生成① のコピー（入寮用 GAS） | `QMATE_GAS_TOKEN_DORM` |

通勤用と入寮用は実行設定の列の並びが違う（入寮用には「タイトル(施策)」の列がない）ので、それぞれの並びで予約行を書きます。
生成した出力シートは、そのスプレッドシートから読んでチェック・入稿します。

ツールから GAS を動かすため、**通勤用・入寮用のそれぞれ**の GAS に呼び出し口を1つ追加します（既存のコードは変えません）。

1. そのスプレッドシートの［拡張機能］→［Apps Script］を開く
2. 左の「ファイル」の＋ →［スクリプト］で `qmate_agent_api` を作り、`gas/qmate_agent_api.gs` の中身を貼り付けて保存
3. 上の関数の選択欄で `setupQmateAgentToken` を選んで［実行］→ 権限を許可 → 実行ログに出た「合言葉」を控える
4. 右上［デプロイ］→［新しいデプロイ］→ 種類の選択で［ウェブアプリ］
   - 次のユーザーとして実行：自分
   - アクセスできるユーザー：全員
5. ［デプロイ］を押し、表示されたウェブアプリの URL を `config/settings.local.json` に入れる
   （`config/settings.local.json.example` をコピーして名前を変え、「通勤」「入寮」の `gas_webapp_url` を書き換える。
   このファイルは ZIP に入っていないので、ZIP を取り直して settings.json を上書きしても消えない）
6. 合言葉は環境変数で渡す：通勤用は `setx QMATE_GAS_TOKEN 合言葉`、入寮用は `setx QMATE_GAS_TOKEN_DORM 合言葉`

入寮用のスプレッドシートも、サービスアカウントのメールアドレスに「編集者」で共有してください。

入稿予定表の「雇用形態」（正社員 → 正社員（人材紹介）に読み替え）「入稿ステータス」「スタンバイキーワード」
「求人ボックスワード」「職種名選択」は行ごとの値を使い（見出しの改行やかっこの補足は無視して列を探します）、
空欄の項目と、入稿予定表にない項目は `schedule_targets` の通勤・入寮それぞれの `defaults` の値を使います。
通勤用の給与パターンは `rules.json` の給与下限から決めます（クルマの夜勤ありなら「35万」）。入寮用は空欄（GAS の初期値）です。
6重め・7軽めは、入稿予定表の「職種名選択」列に職種名（例：防犯カメラの検査）を入れたときだけ実行します。
結果は入稿予定表の「実行結果」列（無ければ見出しの右隣に作る）に書き込みます。

**入稿予定表の入力補助**：`gas/plan_sheet_helper.gs` を通勤用（入稿予定表のある）スプレッドシートの GAS に追加し、
`setupQmatePlanHelper` を1回実行すると、実行設定シートに手入力したときと同じ補助が入稿予定表でも働きます。
職種名選択は 6重め・7軽めの職種名だけのプルダウンになり（同じ会社で30日以内に使った職種名は外し、選ぶと重複警告）、
スタンバイキーワードは通勤／入寮それぞれの候補のプルダウンになります。会社・職種・通勤/入寮を変えると職種名選択は消えます。

### 6. 前回分の取り下げ（takedown）

Q-mate は1つの会社のアカウントに載せられる原稿の数に上限があるので、新しい原稿を入れる前に、
今載っている原稿を消します。これまで手作業でしていたのと同じ手順を自動で行います。

1. CSV取込画面の「テンプレート出力」で、ステータス「公開」の原稿を CSV で取り出す
2. 更新種別（B列）を「削除」、ステータス（C列）を「終了」に書き換える
3. Q-mate は1回に 10,000 件までしか取り込めないので、10,000 件ずつのファイルに分ける
4. 分けたファイルを1つずつ取り込む（前の取り込みが終わるのを待ってから次を入れる）

取り下げは「取り下げ予定表」に書いた行だけで行います（入稿予定表の行を入れただけでは消えません）。
`settings.json` の `takedown.enabled` を true にすると、入稿予定表の「公開」の行の入稿前にも、
その会社の「公開」の原稿をすべて自動で取り下げます（生成とチェックのあと、最初の入稿の前に1回。
下書きだけの行のときと `--no-takedown` を付けたときは行わない）。今は false（使わない）にしています。
取り出したファイルと分けたファイルは `output/取り下げ_会社名_日時/` に残ります。

**取り下げだけをする**ときは、スプレッドシートの「取り下げ予定表」に行を書きます。
実行日になると `schedule`（`run_schedule.bat`）が、入稿予定表の行より先に取り下げます。

| 列 | 内容 |
|---|---|
| 実行日 | この日に取り下げる |
| 会社 | 取り下げる会社 |
| 作成日から／作成日まで | 求人メモの作成日（「22-**261104**-…」の部分）がこの期間の原稿だけ。空欄なら全期間。1日だけなら両方に同じ日付 |
| メモに含む文字 | メモにこの文字を含む原稿だけ（例：`-2-2-7`）。空欄なら指定なし |
| 対象ステータス | 取り出すステータス。空欄なら「公開」 |
| 実行結果 | ツールが書き込む（取り下げた件数と期間） |

1日だけのときは Q-mate のメモ欄に「-261104-」を入れて Q-mate 側で絞ってから取り出し、
期間のときはメモ欄を空欄にして全件を取り出してから、ツール側でメモの作成日が期間内の原稿だけを残します。
どちらの場合も、作成日が読めないメモや期間外の原稿は取り下げません。
`takedown.enabled` が true のときも、同じ会社の取り下げ予定表の行がその日にあれば、入稿前の自動の取り下げ（全件）はしません。

コマンドから直接動かすこともできます。

```bash
# 取り出しと分割だけ（Q-mate は変えない）
python -m qmate_agent takedown --company AspiRove株式会社 --dry-run
# 作成日が 10/22 の原稿だけ取り下げる
python -m qmate_agent takedown --company AspiRove株式会社 --date 2026-10-22
# 作成日が 10/1〜10/22 の原稿を取り下げる
python -m qmate_agent takedown --company AspiRove株式会社 --from 2026-10-01 --to 2026-10-22
```

設定は `settings.json` の `takedown`（取り出すステータス、更新種別、ステータス、1ファイルの件数）です。

## 使い方

```bash
# 出力シートの一覧（検品シートの判定と、このツールのチェック結果も表示）
python -m qmate_agent list

# チェック
python -m qmate_agent check --sheet 出力_G1_GritMate株式会社_1クルマ_20261022

# 入稿前の最終確認だけ（CSV を作って止まる）
python -m qmate_agent upload --sheet 出力_G1_GritMate株式会社_1クルマ_20261022 --dry-run

# 入稿（最初は --headed でブラウザの動きを見ながら）
python -m qmate_agent upload --sheet 出力_G1_GritMate株式会社_1クルマ_20261022 --headed

# 入稿予定表の今日の行を、生成から入稿まで
python -m qmate_agent schedule

# 試すとき：入稿予定表の2行目を、下書き・5件だけで
python -m qmate_agent schedule --row 2 --status 下書き --count 5 --headed
```

Windows では、`qmate_agent` フォルダの `run_schedule.bat`（今日の行を実行）と `test_schedule.bat`
（2行目を、シートの原稿数とステータスのまま試す）をダブルクリックしても同じことができます。その場合、ID・パスワード・合言葉は
`setx QMATE_ID ...` のように一度登録しておきます（登録後はコマンドプロンプトを開き直す）。

毎日自動で動かすときは、Windows の「タスク スケジューラ」で `python -m qmate_agent schedule --yes` を
毎朝実行するように登録します（その時間にパソコンの電源が入っている必要があります）。

### CSV について

見出し行（「職種名|必須」など）も含めて、シートの値をそのまま UTF-8 で書き出します。
最初の1回は、いつも手で書き出している CSV とこのツールの CSV（`output/<シート名>/<シート名>.csv`）を
見比べてください。文字コードや改行が違う場合は `settings.json` の `csv` を変えます。

## 対象外のこと

マニュアルの入稿週の作業のうち、次のものはまだこのツールでは扱っていません。

- 掲載中の原稿の取り出し予約
- 取り出した原稿を非掲載用にして入稿
- 入稿翌日の掲載状況の確認

## テスト

```bash
python -m unittest discover -s tests -t .
```

チェックのテストには、テンプレート(固定列) シートの2行目にある実際の原稿を使っています。
入稿操作のテストは、Q-mate の代わりに手元で立てた仮の画面に対して行っています。

## ファイル

| ファイル | 内容 |
|---|---|
| `config/settings.json` | スプレッドシート ID、シート名、Q-mate の URL と画面の設定 |
| `config/rules.json` | チェックのルール（給与下限、絵文字、削除済みキーワードなど） |
| `qmate_agent/checks.py` | ルールチェック |
| `qmate_agent/ai_review.py` | Claude による中身のチェック |
| `qmate_agent/csv_export.py` | 出力シート → CSV |
| `qmate_agent/uploader.py` | Q-mate へのログインと CSV 入稿 |
| `qmate_agent/sheet.py` | スプレッドシートの読み書き |
| `qmate_agent/takedown.py` | 前回分の取り下げ（テンプレート出力 → 削除・終了に書き換え → 10,000件ずつ取り込み） |
| `qmate_agent/schedule.py` | 入稿予定表 → 実行設定への予約 → GAS での生成待ち |
| `gas/qmate_agent_api.gs` | ツールから GAS の生成を呼び出すための入口（Apps Script に追加する） |
| `gas/plan_sheet_helper.gs` | 入稿予定表の入力補助（職種名選択・スタンバイキーワードのプルダウン、重複警告） |
| `qmate_agent/report.py` | 確認用レポート |
| `state/` | チェック時のシート内容のハッシュと入稿履歴（自動作成） |
| `output/` | レポート・CSV・入稿結果のスクリーンショット（自動作成） |
