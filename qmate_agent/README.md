# Q-mate 入稿チェック・入稿ツール

「【AI用】Q-mate 求人原稿自動生成」スプレッドシートの GAS が作った出力シートを読み込み、
内容をチェックしてから CSV にして Q-mate に入稿します。

原稿を作るのは今まで通り GAS です。このツールが受け持つのは、そのあとの
「確認 → CSV 書き出し → 入稿」です。

## 流れ

```
実行設定シートに予約 → GAS で原稿生成（出力_G1_… シート）→ GAS で検品（検品シート）
   │
   ▼
① check   出力シートを読んでチェック
          ・ルールチェック（下の表）
          ・Claude による中身のチェック（職種名と仕事内容のズレ、キーワードと原稿の食い違い、
            テンプレートの差し込み漏れ、誤字など）
          → output/<シート名>/report.html と CSV を作り、
            スプレッドシートの「AIチェック結果」シートにも書き出す
   │
   ▼
② 人が確認  レポートを見て、問題があればシートを直して ① をやり直す
   │
   ▼
③ upload  CSV を Q-mate に入稿し、結果画面の文言とスクリーンショットを保存
```

upload は、次のどれかに当てはまると入稿せずに止まります。

- check をしていない
- check のあとにシートの内容が変わった
- AI チェックをしていない（`--no-ai` で check した）
- 判定が NG
- 検品シートの判定が ✅OK 以外
- 同じ内容をすでに入稿済み

## ルールチェックの中身

GAS の検品シートと同じ項目に加えて、マニュアルと記録用シートに書かれている運用ルールを見ます。
設定は `config/rules.json` にまとめてあるので、運用が変わったらそこを書き換えます。

| 種類 | 内容 |
|---|---|
| エラー | 「\|必須」の列が空欄 |
| エラー | 給与形態が月給・日給などのときに基本給・労働時間が空欄 |
| エラー | 年齢制限・性別制限が「あり」なのに事由が空欄 |
| エラー | 給与の下限・上限が数値でない、下限が上限より大きい |
| エラー | メモと給与下限・上限・画像番号・勤務地が一致しない |
| エラー | 月給の下限が「2026.10.1～給与下限」を下回る（職種はメモの職種番号、夜勤の有無は勤務時間の書き方で判断） |
| エラー | 勤務時間は夜勤なしなのに求人ボックス用職種名が「夜勤あり」（またはその逆） |
| エラー | 求人ボックス用職種名が50文字を超える |
| 注意 | 応募資格・勤務時間・休日・キャッチコピー・待遇・仕事内容（重め・軽め以外）に絵文字が残っている（10/22 の変更） |
| 注意 | 休日に「年間休日125日」が残っている（10/13 の変更） |
| 注意 | キーワードに削除済みの語（土日祝休み・完全週休二日制・平日のみOK・三交代制）が入っている |
| 注意 | 夜勤なしの原稿に夜勤系のキーワードが入っている |
| 注意 | 同じシート内で求人ボックス用職種名や勤務地が重複している |

会社ごとの応募先メールを確かめたい場合は、`rules.json` の `company_emails` に
`"GritMate株式会社": "xxx@example.com"` のように入れると、メモの会社名と照らし合わせます。

## セットアップ

```bash
cd qmate_agent
pip install -r requirements.txt
playwright install chromium
```

### 1. スプレッドシートを読めるようにする

1. Google Cloud でサービスアカウントを作り、JSON キーを `service_account.json` という名前でこのフォルダに置く
   （git には入らないようにしてあります）
2. スプレッドシートを、サービスアカウントのメールアドレスに「編集者」で共有する

### 2. Claude の API キー

```bash
export ANTHROPIC_API_KEY=...
```

### 3. Q-mate のログイン情報

ID とパスワードはファイルに書かず、環境変数で渡します。

```bash
export QMATE_ID=...
export QMATE_PASSWORD=...
```

### 4. Q-mate の CSV 入稿画面の設定（未完了）

`config/settings.json` の `qmate` のうち、次の3つはまだ仮の値です。
Q-mate の CSV 一括入稿画面を確認してから埋めます。

- `upload_url`：CSV を取り込むページの URL
- `upload_button_selector`：取り込みボタン
- `success_pattern`：取り込みに成功したときに画面に出る文言

調べるときは次のコマンドでブラウザを開き、いつも通り CSV を取り込む操作をすると、
右側に操作内容がコードで表示されます。

```bash
playwright codegen https://m.q-mate.jp/user_sessions/new?layout=login
```

## 使い方

```bash
# 出力シートの一覧（検品シートの判定と、このツールのチェック結果も表示）
python -m qmate_agent list

# チェック
python -m qmate_agent check --sheet 出力_G1_GritMate株式会社_1クルマ_20261022

# 入稿前の最終確認だけ（CSV を作って止まる）
python -m qmate_agent upload --sheet 出力_G1_GritMate株式会社_1クルマ_20261022 --dry-run

# 入稿（最初は --headed でブラウザの動きを見ながら）
python -m qmate_agent upload --sheet 出力_G1_GritMate株式会社_1クルマ_20261022 --headed
```

### CSV について

見出し行（「職種名|必須」など）も含めて、シートの値をそのまま UTF-8 で書き出します。
最初の1回は、いつも手で書き出している CSV とこのツールの CSV（`output/<シート名>/<シート名>.csv`）を
見比べてください。文字コードや改行が違う場合は `settings.json` の `csv` を変えます。

## 対象外のこと

マニュアルの入稿週の作業のうち、次のものはまだこのツールでは扱っていません。

- 掲載中の原稿の取り出し予約
- 取り出した原稿を非掲載用にして入稿
- 入稿翌日の掲載状況の確認

## テスト

```bash
python -m unittest discover -s tests -t .
```

チェックのテストには、テンプレート(固定列) シートの2行目にある実際の原稿を使っています。
入稿操作のテストは、Q-mate の代わりに手元で立てた仮の画面に対して行っています。

## ファイル

| ファイル | 内容 |
|---|---|
| `config/settings.json` | スプレッドシート ID、シート名、Q-mate の URL と画面の設定 |
| `config/rules.json` | チェックのルール（給与下限、絵文字、削除済みキーワードなど） |
| `qmate_agent/checks.py` | ルールチェック |
| `qmate_agent/ai_review.py` | Claude による中身のチェック |
| `qmate_agent/csv_export.py` | 出力シート → CSV |
| `qmate_agent/uploader.py` | Q-mate へのログインと CSV 入稿 |
| `qmate_agent/sheet.py` | スプレッドシートの読み書き |
| `qmate_agent/report.py` | 確認用レポート |
| `state/` | チェック時のシート内容のハッシュと入稿履歴（自動作成） |
| `output/` | レポート・CSV・入稿結果のスクリーンショット（自動作成） |
