# ヒトマネ入稿ツール（hitomane_agent）

求人媒体「ヒトマネ（HITO-Manager）」への入稿と取り下げを、Q-mate 入稿ツール（`qmate_agent`）と同じように自動で行うためのツールです。
設計は `docs/superpowers/specs/2026-11-16-hitomane-agent-design.md` にあります。

今できるのは、**出力シートのチェックと入稿**（第2段階）と、管理画面の **画面調査** です。取り下げは第3段階で作ります。
ヒトマネの管理画面は決まったネットワークからしか開けないので、社内のネットワークにつながったパソコンで動かします。

## 置き場所

GitHub の ZIP（[Download ZIP]）から `hitomane_agent` フォルダを取り出し、今使っている `qmate_agent` フォルダの **となり** に置きます。

```
test-claude-relaxed-clarke-nk8kc9\
  qmate_agent\      ← 今使っている Q-mate 入稿ツール
  hitomane_agent\   ← これ
```

`app.bat`・`survey.bat` は、となりの `qmate_agent` の Python 環境（.venv）とサービスアカウントの鍵（service_account.json）を使います。
となりに無いときは、初回に `hitomane_agent` の中に環境を作ります（数分かかります）。

## ログイン情報

通勤用スプレッドシートの「ヒトマネログイン情報」シート（会社名・ログインID・パスワード・URL・メモ）から読みます。
ヒトマネは担当者ごとにログインIDがあるので、このパソコンで使うログインIDを `config\settings.local.json` に書きます。

```json
{"login_user": "kawana0107"}
```

ログインIDの代わりに、メモの名前（「川名」など）でも選べます。書かなければ、会社名が空欄の行の最初の行を使います。
1回だけ別のIDで動かすときは `survey.bat --user mano0416` のように付けます。
URL の列が空欄なら `https://kanri.hitomgr.jp/m66w/` を開きます。

スプレッドシートが「リンクを知っている全員」に共有されているあいだは、パスワードを使わずに止めます。

## 入稿（操作画面）

`app.bat` をダブルクリックすると、ブラウザに操作画面が開きます（黒い画面は閉じないでください）。
見た目とタブの分け方は Q-mate 版の操作画面と同じです。

**会社の選び方**：ヒトマネは会社ごとに管理画面の URL が違います（例：canal benefits株式会社は `https://kanri.hitomgr.jp/m66w/`、GritMate株式会社は `…/o3h3/`）。ログインID・パスワードはどの会社でも同じです。
画面の右上の「会社」で会社を選ぶと、入稿・取り下げはその会社の管理画面で行います。
会社の一覧は、通勤用スプレッドシートの「ヒトマネログイン情報」シートで、会社名とヒトマネの URL が入った行から読みます。会社を足すときは、そのシートに行を足してください。
入稿の前に、シートの拠点コードがその会社の拠点にあるかを確かめます。会社の選び間違いのときは、ここで止まります。

| タブ | できること |
|---|---|
| 原稿を作る | 入稿予定表の今日の行を、作る → チェック → 入稿 → 実行結果を書く、まで行う。下に、GAS と見比べるための予約リスト（【AI用】の「ヒトマネ実行設定」）（【AI用】の「ヒトマネ実行設定」）|
| 入稿 | 選んだ会社の募集管理の全件数（上限 50,000件まであと何件か）と、出力シートのチェック・入稿 |
| 取り下げ | 掲載開始日の期間で「確認だけ」→ 件数を見て「取り下げる」。今日の確認と、これまでの取り下げの記録 |
| 会社 | 会社の一覧（コード・管理画面の URL・最後に確かめた全件数）。会社ごと・全社まとめてのログインの確認 |
| 更新 | GitHub から最新にする。ダウンロードした ZIP からも更新できる |
| 設定の確認 | 鍵・ログインID・【AI用】スプレッドシート・ログイン情報がそろっているか。ヒトマネにログインできるか |

どのタブでも、いちばん下の「実行の記録」に、動かしているコマンドの様子が出ます。

入稿タブの使い方：

1. 【AI用】ヒトマネ 求人原稿自動生成 の「ヒトマネ出力_…」シートが並びます。GAS の③で原稿を作ってから開いてください。
2. 「チェック」を押すと、シートを読んで入稿前のチェックをします。「結果を見る」で指摘の一覧が開きます。
   NG のシートは入稿できません。シートを直したら、もう一度チェックします。
3. 「入稿」を押すと、ヒトマネにログインして募集管理の全件数を読み、件数と一緒に確認が出ます。「OK」でヒトマネに取り込みます。
   取込ファイル一覧で結果が出るまで待ち、その様子が「実行の記録」に出ます。

入稿しないで止まるのは、チェックをしていない・チェックのあとシートが変わった・NG・同じ内容を入稿済み、のときです。
「既存原稿と同じ募集番号の原稿を上書きせずに取り込む」は外したまま取り込みます（同じ募集番号の原稿は上書きされます）。
1万行を超えるシートは、1万行ずつに分けて順に取り込みます。

## 入稿予定表（担当者は予定を入れるだけ）

Q-mate 版の入稿予定表のヒトマネ版です。【AI用】ヒトマネ 求人原稿自動生成 の「入稿予定表」シートに、担当者が1行＝1回分の予定を入れます。

| 列 | 入れるもの |
|---|---|
| 実行日 | この日に「今日の行をすべて実行」で動く |
| 会社・職種 | プルダウン（会社は＜土台＞の会社情報、職種は 1クルマ〜12シール貼り） |
| 夜勤有無 | チェックボックス |
| 通勤/入寮・雇用形態・入稿ステータス・給与パターン | 空欄なら 通勤・正社員・掲載・基本 |
| 原稿数 | 空欄なら勤務地の数（NG エリアを除く） |
| 画像カテゴリー | 軽作業・製造・工場・入寮 |
| 職種名選択 | 通常の作り方で使う。職種を選ぶとその職種の職種名がプルダウンで出る。6重め/7軽めは必須、ほかは空欄なら自動（選ぶとその職種名だけで作り、使ったことがあれば止める） |
| タイトル末尾ワード | 空欄ならタイトルシートの値 |
| 募集番号の先頭 | 空欄なら、その会社にツールで前回入稿した続き。初めての会社は入れる |
| 実行結果 | ツールが書く |

- 操作画面の「原稿を作る」タブの「今日の行をすべて実行」で、実行日が今日の行を順に、原稿を作る → チェック → その会社のヒトマネに入稿 → 実行結果を書く、まで行います。
  会社は、ログイン情報シートの会社の行と同じ名前で入稿先を決めます。
- 原稿を取り込む前に、その原稿の「お仕事番号」と「拠点」をお仕事情報管理へ取り込みます（ヒトマネの原稿のお仕事番号は、
  お仕事情報管理に登録してある番号でないと「お仕事番号が入力されていません」で取り込めないため。2026-11-19 に確認）。
  登録が失敗したときは原稿は取り込みません。取り下げ（もとからある原稿の入れ直し）では登録しません。
- 入稿しないで止めるのは、チェックが NG・拠点が会社と合わない・上限の 50,000件を超える、のとき。「テスト」は作ってチェックするだけです。
- 実行した行は覚えておき、もう一度押しても入稿し直しません（中身を変えた行は別の予定とみなします）。
- 入稿した原稿の職種名・仕事内容は、このパソコンの記録（`state/usage_local.json`）に残し、次に作るときに避けます。土台の使用履歴シートには書きません。
- 取り下げは予定表では行いません。「取り下げ」タブで条件と件数を確かめてから行います。
- シートが無いときや見出しが崩れたときは、「入稿予定表を作る・整える」で作り直せます（入っている予定は消しません）。
- 職種・分類・勤務地_都道府県を選ぶと、右の「職種名指定」「職種名選択」「勤務地_市区町村」のプルダウンが、選んだ値に合う候補に変わります
  （＜ヒトマネ/施策用＞の土台と同じ動き）。職種名指定は 6重め/7軽めなら分類の候補（分類が空欄なら4つ全部）、それ以外は施策の土台の職種名。
  職種名選択は＜土台＞の職種名（6重め/7軽めは「6重め｜職種名」の形）。選び直して候補から外れた値は消えます。
  シートで選んだときは【AI用】の GAS（`gas/入稿予定表.js`）が付け直し、「入稿予定表を作る・整える」は入っている行すべてに付け直します。
  候補は隠しシート「_入稿予定表_プルダウン（自動生成・編集不要）」にあり、土台や分類ブックを変えたら「入稿予定表を作る・整える」で作り直します。

### 作り方「施策」（＜ヒトマネ/施策用＞と同じ作り方）

入稿予定表の「作り方」を「施策」にした行は、＜ヒトマネ/施策用＞求人原稿自動生成 の GAS（2026-11-18 に読み取りだけで確認）と
同じ作り方で作ります（`hitomane_agent/shisaku.py`）。空欄の行はこれまでどおり「通常」です。

- 土台は ＜土台/施策用＞。6重め/7軽めは ＜ヒトマネ＞重め軽め職種分類 の「…_ヒトマネ用」シートから、「分類」で選んだ範囲を使います
  （このブックは、ツールの読み取り用アカウントに閲覧の共有が必要です）。
- 使える列：フォーマット（新FMT/旧FMT）・職種名指定（空欄=ランダム）・分類・勤務地_都道府県・勤務地_市区町村（空欄=全部）。
  これらの列は「通常」の行では使えません（入っていたら作らずに知らせます）。施策の行では「職種名選択」は使いません。
- 職種名は勤務地ごとにランダムで、同じ会社の同じ勤務地で一度使った職種名は使いません（土台の「会社×勤務地×職種名」の使用履歴と、
  このパソコンの記録で見ます）。
- 画像は3枚（1枚目=画像カテゴリー、2枚目=転職サポート、3枚目=社名入り_<会社名>）。社名入りの画像の無い会社は作れません。
- 募集職種は「急募／職種名／語／語／タイトル末尾ワード」（タイトル編集シート。100文字まで）。仕事内容の前後に「お仕事内容上・下」の文が付きます。
- 給与パターンに「25万」などが使えます（下限 250000〜259999 からランダム、上限は下限×1.25）。
- 旧FMT の原稿は、ヒトマネの「旧原稿形式CSV取込」（`rec_recruitment_migrations/old_import`）から入稿します
  （2026-11-18 の画面調査で、新フォーマットと同じ作りのダイアログと確かめた。実際に旧FMT を取り込んだのはまだ）。

## 原稿を作る（GAS の③の代わり）

ヒトマネ用 GAS（`gas/コード.js`）の「③予約リストを一括実行」の新FMT の作り方を、そのまま Python に移しました（`hitomane_agent/generator.py`）。
Q-mate 版の作り方とは別物です。

- 予約リストは【AI用】の「ヒトマネ実行設定」シート、土台は＜土台＞ヒトマネ 求人原稿自動生成。GAS と同じく、シートの役割はタブ名と見出しで判定します。
- グループ番号（1-1, 1-2 …）が同じ予約行は1つの原稿にまとめます。募集番号の先頭が空の行は、同じ会社の前の行の続きの番号にします。
- 職種名は、使用履歴を見て30日以内に使ったものを避けます。6重め/7軽めで、選んだ職種名が使用履歴にあれば「重複警告」で止まります（GAS と同じ）。
- **使用履歴（職種名・仕事内容・職種名管理）には書きません。** GAS と比べて確かめている間は読むだけにして、GAS から切り替えるときに書くようにします。
- ここで作れるのは新FMT だけです。旧FMT は、入稿予定表で作り方を「施策」にすると作れます。
- 作った原稿は `output/生成/ツール_…/` に置き、すぐにチェックします。入稿タブの「ツールで作った原稿」から、チェック・GAS との比較・入稿ができます。
- 「GAS と比べる」は、同じ予約を GAS の③で作ったシート（ヒトマネ出力_…）と列ごとに見比べます（ランダムな列は値の形と例を並べます）。

GAS の癖も同じにしてあります（仕事内容のシートの見出し「仕事内容」も候補に入る、給与のシートは4行目から読む、など。`generator.py` の先頭に書いてあります）。

### チェックの中身（config
ules.json）

| 種類 | 内容 |
|---|---|
| エラー | 見出しが新フォーマット（192列）と違う、旧フォーマットのシート、原稿が0件 |
| エラー | `#REF!` などのエラー値、Shift_JIS で書けない文字（絵文字など） |
| エラー | 必須の列が空欄、「あり・なし」の列（85列）が「あり」「なし」以外 |
| エラー | 開始日・終了日の形、開始日が終了日より後、ステータスが「掲載」「非掲載」以外 |
| エラー | 基本給が数字でない・最低額が最高額より大きい、お仕事番号と基本給・画像名・勤務地が合わない |
| エラー | 同じ募集番号がシート内に2つ以上 |
| 注意 | 勤務地の重複（ツールで作った原稿は、GAS の⑤検品と同じく予約行ごとに数える）、1枚のシートに拠点コードが2つ以上、いつも入っている列が空欄 |

### コマンドで動かすとき

```
python -m hitomane_agent companies
python -m hitomane_agent login --company o3h3      （--all で全社）
python -m hitomane_agent list
python -m hitomane_agent plan-sheet
python -m hitomane_agent schedule [--row 5] [--dry-run]
python -m hitomane_agent plan
python -m hitomane_agent generate --group 1      （--all で GAS がまだ実行していない全部のグループ）
python -m hitomane_agent compare --generated ツール_…
python -m hitomane_agent upload --company m66w --generated ツール_…
python -m hitomane_agent check --sheet ヒトマネ出力_…
python -m hitomane_agent upload --company GritMate --sheet ヒトマネ出力_… [--dry-run]
```

`--company` には、会社名・会社のコード・会社名の一部のどれを入れてもかまいません。会社が1社しかないときと、settings.local.json に `"company"` を書いたときは省けます。
`login` は、ログインできるかを確かめて、募集管理の全件数と拠点を読むだけです（ヒトマネは変えません）。

`--sheet` の代わりに `--csv ファイル` で CSV（Shift_JIS か UTF-8）も扱えます。
取り込む CSV は、管理画面から取り出した CSV と同じ形（Shift_JIS・改行 CRLF）です。

## 画面調査

`survey.bat` をダブルクリックします。

1. 管理画面にログインし、トップ・ファイル取込ダイアログ（開くだけ）・募集管理・取込ファイル一覧・取出ファイル一覧の画面を順に開きます。
2. 各画面の HTML・画面の写真・リンクの一覧を `output\画面調査_日時\` に保存します。
3. 取り込み・取り下げ・掲載状態の変更はしません。

**CSV の見本**：ダブルクリックで動かすと、CSV の見本も取ります（`survey.bat --sample` と同じ）。募集管理の一覧のいちばん上の原稿の詳細画面を開いて募集番号を読み（読むだけで保存はしません）、その原稿を使います。
決まった原稿を使いたいときは `survey.bat --sample 募集番号` のように番号を付けます。
その1件だけを「ファイル取出予約」して、取出ファイル一覧から CSV をダウンロードし、`取り出し見本.csv` として保存します（原稿は変えません）。
検索結果が1件でないときは、取り出しません。

終わったら、`output\画面調査_日時` フォルダを ZIP にして、Google ドライブなどで送ってください。
ブラウザの動きを見たいときは `--headed` を付けます。

## このあとの予定

- 第3段階：取り下げ（開始日・終了日を2年前、ステータスを非掲載にして取り込み直す）
- そのあと：原稿を作る部分（GAS の③）をツールに移す、Q-mate 入稿ツールとの統合
